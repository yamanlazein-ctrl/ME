# T130 — performance under Node (NFR-02, NFR-03)

Command: `MOTARD_PERF=1 npx vitest run test/perf/volume.test.ts` (skipped unless `MOTARD_PERF=1`; the seed writes about 300,000 rows).

Database: 2,000 customers and 100,000 sale invoices, each with its ledger entry; one deep customer holds 20% of the
documents (20,000), the shape of the desktop volume seed. The whole phone stack runs (repositories, shim over
better-sqlite3), no network.

| Measure                                              | Result (this machine, Node) | Budget in the test |
| ---------------------------------------------------- | --------------------------- | ------------------ |
| Seed of 100,000 invoices + ledger                    | 24.5 s                      | —                  |
| Party search ("عميل 15")                             | 3 ms                        | < 1,000 ms         |
| First statement page (200 rows) of the deep customer | 155 ms                      | < 2,000 ms         |
| Save one sale invoice                                | 51 ms                       | < 2,000 ms         |

These are Node numbers on a development machine. A phone is slower, and op-sqlite with SQLCipher adds encryption cost: the
real figures are task T131 (owner-local) on the reference phone with 100,000 documents.
