# أرشيف Google Drive — دليل الإعداد والاستخدام والاسترداد

## 1. متطلبات خارجية (بيد المالك فقط)

1. **Google Cloud project**: أنشئ مشروعًا في console.cloud.google.com.
2. **تفعيل Drive API**: APIs & Services → Library → Google Drive API → Enable.
3. **OAuth consent screen**: External → أضف التطبيق. ⚠️ في وضع Testing تنتهي صلاحية refresh tokens خلال 7 أيام — للإنتاج انشر التطبيق (Publish). النطاق المطلوب: `https://www.googleapis.com/auth/drive.file` (وصول لملفات التطبيق فقط) + `openid email`.
4. **OAuth client**: Credentials → Create Credentials → OAuth client ID → **Desktop app**. انسخ الـ Client ID (ليس سرًّا لتطبيقات سطح المكتب).

## 2. المتغيرات والبيانات الحساسة

- **عميل OAuth مُضمَّن في نسخة الإصدار (مُفضَّل):** يُمرَّر وقت البناء عبر متغيري البيئة
  `MOTARD_GOOGLE_CLIENT_ID` (و`MOTARD_GOOGLE_CLIENT_SECRET` إن أصدره Google) — لا يُحفظ في المستودع.
  النسخة المبنية بدونهما لا تحتوي عميلًا، فيُعرض للمسؤول «إعدادات متقدمة» لإدخال معرّف العميل يدويًا.
- العميل المُدخل يدويًا (override) و refresh token يُخزَّنان في `%LOCALAPPDATA%\MotardERP\keys\google.dat`
  مختومين بـ DPAPI بمفتاح إنتروبيا خاص (منفصل عن `secrets.dat`).
- refresh token لا يغادر خلفية Rust أبدًا: لا localStorage، لا frontend، لا الخادم الخلفي، لا سجلات.
- access token قصير العمر (~ساعة) يُدفع إلى الخادم الخلفي (`POST /api/desktop/runtime/drive-token`) ويُحدَّث
  تلقائيًا قبل الانتهاء بخمس دقائق.
- الربط مرتبط بالعميل الذي أُنشئ به: تغيير العميل يلغي الربط ويتطلب إعادة الربط. الربط الذي أُنشئ في 3.0.6
  يبقى صالحًا بعد التحديث.

## 3. هيكل المجلدات في Drive

`<اسم الشركة> - أرشيف النظام / <السنة> / <YYYY-MM — الشهر العربي> / <الفئة>`

الفئات السبع (المصدر الوحيد: `packages/shared/src/archivePaths.ts`، والأرشيف المحلي على سطح المكتب يستخدم
الأسماء نفسها): فواتير الدخول، فواتير الخروج، المرتجعات، إرساليات واستلامات الطباعة، كشوف الحسابات،
الصندوق والتقارير، نسخ النظام الاحتياطية.

الملفات:

- لكل فاتورة: `YYYY-MM-DD_رقم-الفاتورة_اسم-الجهة.csv` (`_ملغاة` للملغاة)، ومعها PDF
  `YYYY-MM-DD_رقم-الفاتورة_sale|entry.pdf` حين يكون التطبيق المكتبي (المُصيِّر) يعمل.
- مصروفات الشهر: `YYYY-MM-01_مصروفات-الشهر.csv`.
- النسخة الاحتياطية الموثَّقة الأحدث: `backup-*.zip` في «نسخ النظام الاحتياطية».

كل ملف مرتبط بمعرّف المستند الثابت: تعديل الفاتورة أو إلغاؤها أو تغيير اسم الجهة يحدّث **الملف نفسه** في
Drive ولا ينشئ نسخة ثانية.

### متى يُؤرشف الشهر؟

- بعد **انتهائه** فقط (أرشيف أكتوبر يُرفع في نوفمبر)، وكل شهر فائت لم يُؤرشف يُستكمل (حتى 24 شهرًا للخلف).
- الشهر لا يُعدّ مؤرشفًا إلا حين تُرفع **كل** ملفاته. ما تبقّى في القائمة يُستكمل في الجولات التالية (كل 6 ساعات).
- تعديل مستند بعد أرشفة شهره يجعل الشهر مستحقًا من جديد، فيُحدَّث ملفه في Drive.
- زر «المزامنة الآن» يرفع الشهر الجاري أيضًا، لكنه لا يعدّ الشهر الجاري مؤرشفًا: يُعاد أرشيفه بعد انتهائه.
- النسخة الاحتياطية الموثَّقة الأحدث تُرفع في كل جولة (مرة واحدة لكل نسخة)، ويُتحقق من محتواها في Drive.

## 4. الجهاز الأساسي

- جهاز واحد فقط لكل شركة يرفع الأرشيف (يُحدَّد في قسم `drive` من الإعدادات ويُزامَن عبر المحور).
- الأجهزة الأخرى تعرض الحالة فقط. أي محاولة رفع من جهاز غير أساسي تُرفض في الـ backend (fail-closed).
- **نقل الدور**: حدّث `coordinatorDeviceId` (واجهة الإعدادات على الجهاز الجديد). الجهاز القديم يُرفض فورًا بعد وصول المزامنة. لا failover تلقائي.

## 5. الاستعادة من نسخة Drive

1. حمّل ملف `backup-*.zip` من مجلد «نسخ النظام الاحتياطية».
2. الإعدادات → النسخ الاحتياطي → الاستعادة الكاملة (نفس مسار FullRestore المحلي).
3. الاستعادة تتحقق من البصمة والسجل تلقائيًا (v3 pipeline).

## 6. استكشاف الأخطاء

| الحالة                                | السبب                         | الإجراء                                             |
| ------------------------------------- | ----------------------------- | --------------------------------------------------- |
| «انتهت صلاحية التفويض»                | سحب التفويض أو انتهاء Testing | أعد ربط الحساب                                      |
| «هذا الجهاز ليس جهاز الأرشفة الأساسي» | جهاز ثانوي                    | ارفع من الجهاز الأساسي                              |
| ملفات معلقة تزيد                      | Drive غير متاح                | تعود القائمة تلقائيًا عند العودة؛ لا تحجب المعاملات |
| عمليات فاشلة بعدها blocked            | رفض Google                    | أعد الربط ثم «إعادة» لكل ملف                        |

## 7. قائمة اختبار ما قبل الإصدار (بيد المالك)

- [ ] ربط حقيقي بحساب تجريبي → ظهور البريد في الإعدادات
- [ ] «اختبار الاتصال» ينجح
- [ ] مزامنة الآن → ظهور المجلدات والملفات في Drive بالأسماء الصحيحة
- [ ] إغلاق التطبيق أثناء رفع → إعادة تشغيل → لا تكرارات
- [ ] فصل الحساب من حساب Google (revocation) → تظهر الحالة معطّلة في التطبيق
- [ ] إعادة الربط → «إعادة» للملفات المعطلة → تُرفع
- [ ] تنزيل نسخة احتياطية من Drive → استعادة كاملة ناجحة على جهاز آخر
