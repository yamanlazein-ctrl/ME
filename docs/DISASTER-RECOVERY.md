# 🛡️ دليل حماية بياناتك واسترجاعها بعد الكوارث

**للزبون الكريم:** هذا الدليل يشرح بخطوات بسيطة كيف تحمي بيانات محاسبتك، وكيف تستعيدها
بالكامل لو سُرق الجهاز أو تعطل. اقرأه مرة واحدة واحفظ مكانه.

---

## أولاً: ما الذي تشمله النسخة الاحتياطية؟

النسخة ملف **ZIP واحد** يحتوي على كل شيء:

| المحتوى | التفاصيل |
|---------|----------|
| 📊 قاعدة البيانات | الفواتير، العملاء والموردين، المخزون واللفافات، سندات القبض والصرف، دفتر الأستاذ، جلسات الصندوق وحركاته اليدوية، المصاريف، المرتجعات، الطلبات، سجل الترقيم |
| 📎 الملفات المرفقة | الصور والمستندات المرفوعة مع بياناتها الرابطة بالفواتير |
| ⚙️ الإعدادات | بيانات الشركة، العملات، المستخدمون، إعدادات الطباعة |

> ⚠️ **مهم:** النسخة تحتوي على **بياناتك فقط** وليس البرنامج نفسه. لذلك الاسترجاع يتطلب
> تثبيت النظام أولاً على الجهاز الجديد (انظر الخطوات أدناه).

---

## ثانياً: كيف تأخذ نسخة احتياطية؟ (زر واحدة)

1. سجّل الدخول بحساب **المدير (Admin)**.
2. افتح: **الإعدادات ← النسخ الاحتياطي**.
3. اضغط **«تصدير نسخة كاملة»** — سيُحمّل ملف ZIP تلقائياً إلى مجلد التنزيلات.
4. انقل الملف إلى **فلاشة USB أو تخزين سحابي** (Google Drive مثلاً). لا تكتفِ بالقرص نفسه!

### 📅 جدول مقترح للنسخ:
- **يومياً** في نهاية دوام العمل إن كان فيه فواتير كثيرة.
- **أسبوعياً** كحد أدنى.
- احتفظ بـ **3 نسخ على الأقل**: على الفلاشة + السحابة + الجهاز.

---

## ثالثاً: سيناريو الكارثة — سرقة/تعطل الجهاز واسترجاع البيانات

على **جهاز جديد نظيف تماماً**، نفّذ الخطوات التالية بالترتيب:

### الخطوة 1: تجهيز الأساسيات
```bat
:: حمّل وثبّت على الجهاز الجديد:
::   1) Node.js (نسخة LTS) من nodejs.org
::      - فعّل خيار "Automatically install the necessary tools"
::   2) PostgreSQL من postgresql.org (احفظ كلمة مرور postgres التي ستدخلها!)
```

### الخطوة 2: إنشاء قاعدة بيانات فارغة
افتح **SQL Shell (psql)** من قائمة Start ثم:
```sql
CREATE DATABASE erp;
\q
```

### الخطوة 3: تثبيت النظام
انسخ مجلد المشروع إلى الجهاز الجديد (من فلاشة/بريد/سحابة)، ثم افتح CMD داخل مجلد `backend`:
```bat
copy .env.example .env
::  عدّل ملف .env وضَع رابط القاعدة وكلمة المرور:
::  DATABASE_URL=postgresql://postgres:كلمة_المرور@localhost:5432/erp

npm install
npm run db:migrate
```
> `db:migrate` ينشئ كل الجداول. النسخة الاحتياطية ستمتلئ فوقها بالخطوة التالية.

### الخطوة 4: الاسترجاع (نقطة العودة للحياة)
ضع ملف النسخة `fabric-erp-full-backup-XXXX.zip` داخل مجلد `backend` ثم:
```bat
npm run db:restore fabric-erp-full-backup-XXXX.zip
```
سيقوم السكربت تلقائياً بـ:
- فك ضغط النسخة
- تفريغ أي بيانات قديمة لنفس الحساب (استرجاع قابل للتكرار بأمان)
- إعادة إدخال **كل** الجداول بترتيب آمن يمنع التعارض
- إعادة الملفات المرفقة إلى مجلد `uploads`
- طباعة عدد الصفوف المستعادة كإثبات

### الخطوة 5: التشغيل
```bat
:: من مجلد backend
npm run dev

:: ومن مجلد المشروع الرئيسي (نافذة أخرى)
npm run dev
```
افتح المتصفح على العنوان المعروض، وسجّل دخولك بنفس حسابك السابق —
**كل بياناتك كما كانت لحظة أخذ النسخة بالضبط.**

---

## رابعاً: أسئلة شائعة

**س: نسيت أخذ نسخة قبل عطل القرص، هل هناك أمل؟**
ج: البيانات غير المُنسوخة غير قابلة للاسترجاع من طرف النظام. لهذا نؤكد على النسخ اليومي.

**س: هل يمكن استرجاع النسخة على أكثر من مستأجر/شركة؟**
ج: النسخة مرتبطة بحساب شركة واحدة (tenant). لكل شركة نسختها الخاصة بها.

**س: فشل الاسترجاع برسالة خطأ؟**
ج: تأكد أنك نفذت `npm run db:migrate` بنجاح أولاً، وأن ملف `.env` يشير للقاعدة الصحيحة.
